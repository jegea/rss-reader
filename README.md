# RSS Reader

A self-hosted RSS reader built as a personal software development project.

RSS Reader provides a simple interface for managing RSS feeds, organizing sources into categories, and keeping track of articles. The project is an ongoing initiative, with a focus on clean architecture, maintainability, security, and modern development practices.

> **Project status:** Active development. Features, architecture, and documentation may evolve over time.

## Features

- **Feed management:** Add and manage RSS/Atom feed sources.
- **Category management:** Organize feeds into custom categories.
- **Article reading:** Browse articles from subscribed sources.
- **Reading status:** Mark articles as read or unread.
- **Bookmarks:** Mark articles as starred for later reference.
- **Article details:** Read expanded article content within the application.
- **Feed synchronization:** Retrieve and update articles from subscribed feeds.
- **Filtering:** Browse articles by category, source, reading status, and starred status.

## Getting Started

### Prerequisites

Make sure you have the following tools installed:

- [Docker](https://www.docker.com/)
- [Docker Compose](https://docs.docker.com/compose/)

The application runs inside Docker containers, so installing Python and Node.js locally is not required for the standard development workflow.

### 1. Clone the repository

```bash
git clone <repository-url>
cd rss-reader
```

Replace `<repository-url>` with the URL of your repository.

### 2. Configure environment variables

Create your local environment file from the example:

```bash
cp .env.example .env
```

Edit `.env` and configure the PostgreSQL password:

```dotenv
POSTGRES_DB=rss_reader
POSTGRES_USER=rss_reader
POSTGRES_PASSWORD=change_me_locally

DATABASE_URL=postgresql+psycopg://rss_reader:change_me_locally@db:5432/rss_reader

API_PORT=8010
WEB_PORT=5175
POSTGRES_PORT=5440
```

Use a suitable local password and make sure the password in `DATABASE_URL` matches `POSTGRES_PASSWORD`.

**Important:** Never commit your `.env` file or real credentials to the repository.

### 3. Start the application

Build and start the containers:

```bash
docker compose up --build -d
```

This starts three services:

| Service | Description | Local address |
|---|---|---|
| Web | React development server | http://localhost:5175 |
| API | FastAPI application | http://localhost:8010 |
| Database | PostgreSQL 17 | localhost:5440 |

The API documentation is available at:

- Swagger UI: http://localhost:8010/docs
- ReDoc: http://localhost:8010/redoc

### 4. Apply database migrations

Once the containers are running, apply the database migrations:

```bash
docker compose exec api alembic upgrade head
```

This creates or updates the database schema to the latest migration.

The application is now ready to use.

## Database Migrations

Database schema changes are managed with Alembic.

### Generate a migration

After modifying SQLAlchemy models, generate a migration:

```bash
docker compose exec api alembic revision --autogenerate -m "Describe the changes"
```

Review the generated migration before applying it. Autogenerated migrations should always be checked manually.

### Apply migrations

```bash
docker compose exec api alembic upgrade head
```

### Check the current migration

```bash
docker compose exec api alembic current
```

### View migration history

```bash
docker compose exec api alembic history
```

## Testing

The backend test suite uses Pytest and a dedicated PostgreSQL database.

The test database must be created separately from the development database.

### 1. Create the test database

Make sure the database container is running:

```bash
docker compose up -d db
```

Create the test database:

```bash
docker compose exec db createdb -U rss_reader rss_reader_test
```

This only needs to be done once for a persistent local database volume.

### 2. Run backend tests

```bash
docker compose exec \
  -e TEST_DATABASE_URL="postgresql+psycopg://rss_reader:change_me_locally@db:5432/rss_reader_test" \
  api pytest
```

Replace `change_me_locally` with the password configured in your `.env` file.

### 3. Run tests with coverage

```bash
docker compose exec \
  -e TEST_DATABASE_URL="postgresql+psycopg://rss_reader:change_me_locally@db:5432/rss_reader_test" \
  api pytest --cov=app --cov-report=term-missing
```

This displays the test coverage for each application module, including lines that are not currently covered by tests.

The test fixtures create the required database tables and roll back individual test transactions to keep tests isolated.

## Security Considerations

Feed ingestion involves retrieving content from external URLs. Since user-provided feed URLs can potentially be abused to access internal services, feed fetching includes several security protections.

Current protections include:

- Only HTTP and HTTPS feed URLs are accepted.
- URLs containing embedded credentials are rejected.
- DNS resolution and IP addresses are validated to prevent requests to non-public addresses.
- Connections use validated IP addresses while preserving the original hostname for HTTP Host headers and TLS SNI.
- Redirects are handled manually and validated individually.
- The number of redirects is limited.
- Feed downloads have a maximum size limit of 5 MB.
- HTTP requests have a timeout limit.
- Environment-based proxy configuration is disabled for feed requests.

### Current limitations

- **No authentication or authorization:** The application currently has no user authentication or access control. It is intended for local development and personal use.
- **No multi-user isolation:** Data is not separated between users.
- **External feed availability:** Feed retrieval depends on the availability and behavior of third-party servers.
- **Security hardening is ongoing:** Feed ingestion and other application components require continued testing and review.

**Deployment warning:** Do not expose this application publicly or use it as a multi-user service without implementing authentication, authorization, appropriate network restrictions, and additional security controls.
